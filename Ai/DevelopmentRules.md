# قواعد اجرای task

## پیش از تغییر

1. دستورهای `AGENTS.md` مرتبط، اسناد معرفی و task انتخاب‌شده را بخوان.
2. وضعیت Git، کد موجود، وابستگی‌ها و تست‌ها را بررسی کن. کار موجود را بازنویسی یا حذف نکن.
3. پیش‌نیازهای task را با کد تطبیق بده؛ وضعیت ثبت‌شده به‌تنهایی اثبات تکمیل نیست.
4. ابتدا نیازمندی، مدل داده، قرارداد API و جریان UI همان قابلیت را مشخص کن و تصمیم‌های مؤثر را ثبت کن.
5. انتخاب‌های فنی کوچک را با الگوهای پروژه حل کن. ابهام مؤثر بر رفتار محصول را روشن کن؛ تا دریافت پاسخ روی بخش‌های مستقل ادامه بده.

## حین اجرا

- فقط محدودهٔ task انتخاب‌شده را اجرا کن؛ نیاز جدید را به کار آینده منتقل کن.
- سادگی، نگهداری‌پذیری و امکان توسعه اولویت دارند. از افزودن کتابخانه بدون نیاز روشن خودداری کن.
- TypeScript واقعی، API layer مستقل، Componentهای کوچک، Theme مرکزی و جداسازی منطق از UI رعایت شوند.
- فارسی و RTL شامل Emotion، Portal، Dialog، Drawer، جدول و تقویم است؛ `dir` به‌تنهایی کافی نیست.
- عملیات Async باید Loading، Empty، Error و Success مناسب داشته باشند. خطای خام سرور در UI نمایش داده نشود.
- Backend مسئول Validation و Authorization است؛ مخفی‌کردن دکمه جایگزین کنترل مجوز نیست.
- دسترسی به داده‌های وابسته به سالن با زمینهٔ معتبر سالن محدود شود؛ شناسهٔ ارسالی کاربر قابل اعتماد نیست.
- اطلاعات حساس، رمز، OTP و Token در مستندات یا Log ثبت نشوند.
- Migration و تغییر قرارداد API باید اثرشان بر داده‌ها و مصرف‌کننده‌های موجود مشخص باشد.
- نیازمندی اولیه را بدون ثبت دلیل و تصمیم جدید تغییر نده. تعارض حل‌نشده را شفاف مطرح کن.

## تحویل و ادامه

- معیارهای پذیرش task را با شواهد بررسی کن؛ نوشتن کد به‌تنهایی به معنی تکمیل نیست.
- تست‌های مرتبط و Build/Type-check موجود را اجرا کن. برای رفتارهای حساس مانند مجوز، تداخل رزرو و پرداخت تست معنادار اضافه کن.
- فرمان اجراشده، نتیجه و محدودیت محیط را دقیق ثبت کن؛ تست اجرا‌نشده را موفق اعلام نکن.
- `ProjectStatus.md` را به‌روز کن: وضعیت فاز، بخش انجام‌شده، فایل‌های مهم، بررسی‌ها، مانع و قدم بعد.
- تصمیم‌های جدید را همراه دلیل در `Decisions.md` ثبت کن. مطالب تاریخی را با وضعیت فعلی اشتباه نگیر.
- اگر کار نیمه‌تمام ماند، همان task را `in_progress` یا `blocked` ثبت کن؛ کار باقی‌مانده و شرط ادامه مشخص باشد.
- بدون درخواست کاربر Commit، Push یا شروع فاز بعد انجام نده.
