# نقطهٔ شروع همکاری

این فایل را در ابتدای هر جلسه بخوان. هدف، توسعهٔ مرحله‌ای SaaS مدیریت سالن زیبایی با پنل مدیریت و اپلیکیشن مشتری است. رابط فارسی و RTL است؛ پنل Desktop First و اپلیکیشن مشتری Mobile First خواهد بود.

## ترتیب مطالعه

1. [BasePrompt.md](BasePrompt.md): نیازمندی‌های اولیه و چشم‌انداز کامل محصول؛ مطالعهٔ اولیهٔ آن الزامی است.
2. [DevelopmentRules.md](DevelopmentRules.md): قواعد مشترک اجرای همهٔ کارها.
3. [ProjectStatus.md](ProjectStatus.md): آخرین وضعیت ثبت‌شده، تحویل‌ها و ادامهٔ کار.
4. [Decisions.md](Decisions.md): تصمیم‌های قطعی و پرسش‌های باز.
5. [tasks/README.md](tasks/README.md): ترتیب فازها و وابستگی‌ها.
6. فقط فایل task معرفی‌شده توسط کاربر و فایل‌های کد مرتبط با آن.

## اصول پروژه

- Backend: Laravel / PHP، API محور، دیتابیس هدف MySQL یا MariaDB.
- Frontend: React / TypeScript / Vite / MUI، ساختار ماژولار و Theme مرکزی.
- منطق کسب‌وکار، مجوزها، اعتبارسنجی و محاسبهٔ نوبت در Backend قرار می‌گیرند.
- از ابتدا زمینهٔ سالن و جداسازی داده‌ها در نظر گرفته شود؛ پیچیدگی SaaS کامل تدریجی است.
- Blade می‌تواند پوستهٔ بارگذاری React باشد؛ صفحات محصول به Viewهای سروری وابسته نشوند.
- BasePrompt چشم‌انداز اولیه است؛ مثال‌ها و پیشنهادهای آن به معنی تصمیم نهایی یا قابلیت پیاده‌شده نیستند.

## شیوهٔ استفاده

برای آشنایی فقط همین فایل را معرفی کن. برای اجرا، نام دقیق یکی از فایل‌های `Ai/tasks/` را نیز بده. خواندن معرفی به‌تنهایی مجوز شروع پیاده‌سازی نیست. اجرای یک task مجوز شروع خودکار فاز بعدی نیست.

پس از هر اجرا، وضعیت واقعی و نتایج بررسی‌ها در `ProjectStatus.md` و تصمیم‌های جدید در `Decisions.md` ثبت می‌شوند تا جلسهٔ بعد به حافظهٔ گفتگو وابسته نباشد.

نمونه‌های آماده در [StartPrompts.md](StartPrompts.md) قرار دارند.

راهنمای اجرای برنامه و مسیرهای پیش‌نمایش در [LocalDevelopment.md](LocalDevelopment.md) قرار دارد. برای اجرای پروژه روی Ubuntu و اتصال گوشی از شبکه محلی یا Cloudflare Tunnel، [UbuntuMobileAccess.md](UbuntuMobileAccess.md) را بخوان.
