# تسک 01b — زیرساخت API و احراز هویت

## هدف و منابع

تکمیل Foundation پس از Layoutهای تسک `01-foundation.md`، پیش از مدیریت سالن. ابتدا `Ai/README.md` و منابع آن خوانده شوند. مرجع: بخش‌های 22 تا 27، 30 تا 32 و 35 تا 39 در BasePrompt.

## تصمیم‌های لازم

دیتابیس توسعه، روش Login، Session/Token، Provider احتمالی OTP، ماتریس نقش‌ها، عضویت کاربران و Tenant Context مشخص و ثبت شوند. پیشنهادهای BasePrompt تصمیم قطعی نیستند.

## محدوده

1. قرارداد پاسخ و خطای API، Validation و API layer مستقل از UI را ایجاد کن.
2. مدل حداقلی سالن، عضویت کاربران و مجوزهای Backend را بساز.
3. ورود، خروج و دریافت کاربر فعلی را پیاده کن؛ کنترل دسترسی Backend و مسیرهای Frontend هماهنگ باشند.
4. پوسته‌های پنل و مشتری را به هویت واقعی متصل کن و ورودی پیش‌نمایش را با جریان ورود مناسب جایگزین کن.
5. Loading و خطاهای شبکه، 401، 403 و 422 را مدیریت کن.
6. پیکربندی محیط و دستورهای اجرای محلی را بدون اطلاعات محرمانه مستند کن.

## خارج از محدوده

CRUD دامنه، رزرو، پرداخت و قابلیت‌های کامل اپ مشتری.

- [x] کاربر فاقد مجوز و دسترسی بین سالن‌ها در Backend رد می‌شوند؛ تست مرتبط وجود دارد.
