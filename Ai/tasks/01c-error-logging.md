# تسک 01c — ثبت خطاهای سرور در دیتابیس

## هدف

ثبت مرکزی خطاهای غیرمنتظره Backend برای بررسی و اتصال احتمالی آینده به کانال‌های هشدار مانند Telegram، بدون ذخیره داده‌های حساس درخواست.

## تصمیم‌ها

- خطاهای HTTP با کد ۵۰۰ و بالاتر و Exceptionهای غیرمنتظره ثبت می‌شوند. خطاهای عادی ۴xx جدول را شلوغ نمی‌کنند، به‌جز خطاهای دامنه‌ای مهم و منتخب مانند شکست تأیید OTP.
- body، query string، Cookie و Headerهای درخواست ذخیره نمی‌شوند.
- مقادیر رایج حساس در متن Exception و شماره موبایل ایرانی پیش از ذخیره مخفی می‌شوند.
- شکست خود سامانه ثبت خطا نباید Exception تازه یا چرخه گزارش بی‌نهایت ایجاد کند.
- هر رکورد `reference_id` یکتا و فیلد nullable برای زمان رفع خطا دارد تا UI مدیریتی آینده روی همین داده ساخته شود.

## محدوده پیاده‌سازی‌شده

- جدول `error_logs` و مدل `ErrorLog`.
- سرویس `DatabaseExceptionReporter` و اتصال آن به Exception pipeline لاراول.
- ذخیره محیط، نوع و پیام امن‌شده، کد وضعیت، مسیر و متد، نام Route، کاربر، سالن، فایل، خط و Stack Trace.
- تست ثبت خطای سرور، حذف اطلاعات حساس و نادیده‌گرفتن خطای Client.
- ثبت امن خطاهای جریان تأیید OTP با وضعیت ۴۲۲، بدون ذخیره کد یا payload ورودی.

## خارج از محدوده
