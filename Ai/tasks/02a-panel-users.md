# تسک 02a — مدیریت کاربران پنل سالن

## هدف

اولین زیرتسک فاز 02، مدیریت اعضای دارای دسترسی به پنل است. هویت کاربر در جدول `users` سراسری و نقش و وضعیت دسترسی او در هر سالن داخل `salon_user` نگهداری می‌شود.

## تصمیم‌ها

- فقط `salon_owner` و `super_admin` می‌توانند کاربران پنل را مدیریت کنند.
- نقش‌های محصول «مدیر سالن»، «کارکنان» و «مشتری» هستند و به‌ترتیب با `salon_owner`، `employee` و `customer` ذخیره می‌شوند. نقش قدیمی `manager` با migration به مدیر سالن تبدیل می‌شود.
- شماره موبایل شناسه یکتای سراسری کاربر است. افزودن موبایل موجود، عضویت همان حساب را در سالن ایجاد یا فعال می‌کند.
- دکمه حذف، User را Soft Delete می‌کند؛ حسابی که در سالن دیگری نیز عضویت دارد از این مسیر قابل حذف سراسری نیست.
- مدل User دارای `deleted_at` و قابلیت Soft Delete سراسری است؛ این عملیات از حذف عضویت یک سالن مستقل است.
- آخرین مالک فعال سالن قابل غیرفعال‌سازی یا تنزل نقش نیست.
- تمام خواندن و نوشتن‌ها از Salon Context معتبر Backend استفاده می‌کنند و شناسه سالن از payload پذیرفته نمی‌شود.

## محدوده

- API فهرست صفحه‌بندی‌شده، جستجو و فیلتر نقش/وضعیت.
- ایجاد، مشاهده، ویرایش، تغییر نقش، فعال‌سازی و غیرفعال‌سازی عضو پنل.
- UI فارسی و RTL با Loading، Empty، Error و Success.
- آپلود تصویر کاربر با فرمت JPG/PNG/WebP و سقف ۲ مگابایت، پیش‌نمایش و جایگزینی تصویر قبلی.
- انتخاب دسترسی منو برای نقش کارکنان؛ مجوزها روی عضویت همان سالن ذخیره و در منو و Guard مسیر اعمال می‌شوند.
- پروفایل شخصی مدیر و کارکنان در `/panel/profile` برای ویرایش نام، ایمیل، تاریخ تولد و تصویر؛ موبایل فقط خواندنی است.
- صفحات `/panel/customers` و `/panel/employees` از همان CRUD مشترک با فیلتر ثابت `customer` و `employee` استفاده می‌کنند و نقش فرم در آن‌ها قفل است.
- تست دسترسی نقش‌ها، جداسازی سالن، اعتبارسنجی و حفاظت از آخرین مالک.

## خارج از محدوده

- CRUD مشتریان، مشخصات تخصصی کارکنان، خدمات، ساعات کاری، دعوت پیامکی و حذف دائمی حساب.
