## تحویل 2026-10-22 — نصب PWA مشتری و اصلاح فرم احراز هویت

- نسخه نصب‌شدنی مشتری با manifest پویا، آیکن سالن در اندازه‌های ۱۸۰/۱۹۲/۵۱۲، metadata نصب iOS، صفحه عمومی `/app/install`، راهنمای Android/iOS و لینک نصب در خانه/پاورقی پیاده شد. Controller و مسیرهای manifest/icon مستقل از catch-all هستند.
- فایل `resources/js/pwa/service-worker.js` در Build به `public/sw.js` نسخه‌دار تبدیل می‌شود. قطع اتصال صفحه راهنما نمایش می‌دهد؛ داده خصوصی و عملیات رزرو/سفارش آفلاین ذخیره نمی‌شوند. اعلان نسخه جدید با اقدام کاربر Reload می‌کند.
- باگ ورود→ثبت‌نام: علت reuse شدن AuthPage و باقی‌ماندن `step=code` بود. Routeهای دارای key مستقل، حفظ شماره و مقصد و بی‌اثرکردن پاسخ async صفحه قبلی اضافه شدند. برگشت به ورود نیز فرم کد و نام قبلی را پاک می‌کند.
- بررسی‌ها: `npm run typecheck` و `npm run build` موفق؛ هشدار حجم chunk بزرگ همچنان وجود دارد. PHPUnit: ۱۳۵ تست و ۸۶۳ assertion موفق؛ Pint موفق. پنج تست Feature جدید PWA شامل هویت عمومی، fallback، PNG واقعی و metadata هستند.
- تست مرورگر Chrome روی Build: مسیر نبود حساب→ثبت‌نام، نمایش نام‌ها، حفظ شماره، تغییر معکوس، بی‌اثر بودن پاسخ OTP دیرهنگام و payload/redirect ثبت‌نام موفق بررسی شدند. APIهای این تست شبیه‌سازی شدند و پیامک واقعی ارسال نشد.
- مرورگر PWA: manifest بدون خطای parse، worker فعال، قطع اتصال و بازگشت، عدم Cache پاسخ خصوصی، راهنمای iOS، نمایش واکنش‌گرا در عرض ۳۶۰ تیره/۱۴۴۰ روشن و توضیح HTTPS روی HTTP شبکه بررسی شدند. تعامل دکمه نصب با رویداد شبیه‌سازی‌شده بررسی شد؛ نصب واقعی روی گوشی انجام نشده و Chrome تست فقط محدودیت incognito برای نصب گزارش کرد.
- نصب واقعی گوشی نیازمند HTTPS معتبر است؛ لینک عمومی منتشر نشده است. Build فعلی با Laravel تنها کار می‌کند؛ npm dev برای توسعه است و worker جدید در حالت dev ثبت نمی‌شود.

- بررسی تکمیلی PWA با تغییر موقت worker و بازگرداندن فایل: نسخه جدید بدون Reload خودکار منتظر ماند و پس از کلیک «به‌روزرسانی» فعال و صفحه Reload شد. بسته کاری محدود در `Ai/tasks/06f-customer-pwa.md` ثبت شد.
