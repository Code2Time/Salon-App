# اجرای Layoutها

## پیش‌نیاز

PHP و Composer مطابق `composer.json`، Node.js سازگار با Vite نصب‌شده، و وابستگی‌های `composer install` و `npm ci` لازم‌اند. PHP مورد استفاده باید افزونه‌های مورد نیاز Laravel، از جمله `mbstring` و `openssl`، را فعال داشته باشد.

اگر `.env` وجود ندارد، از `.env.example` کپی بگیر و `php artisan key:generate` اجرا کن. تنظیمات محیط موجود را بازنویسی نکن. اگر Session یا Cache روی دیتابیس تنظیم شده، دیتابیس و Migrationهای لازم باید آماده باشند؛ برای پیش‌نمایش بدون دیتابیس می‌توان در محیط توسعه `SESSION_DRIVER=file` و `CACHE_STORE=file` تنظیم کرد.

پس از روشن‌کردن MySQL و ساخت دیتابیس تنظیم‌شده در `.env`:

```sh
php artisan migrate --seed
php artisan storage:link
```

دستور `storage:link` برای نمایش تصاویر آپلودشدهٔ پروفایل و دسته‌بندی‌ها الزامی است و باید در هر محیط پس از استقرار یک‌بار اجرا شود.

حساب‌های آزمایشی Seeder شامل مدیر سالن با شماره `09333218766`، مشتری با شماره `09111111111` و دو کارمند با شماره‌های `09222222222` و `09333333333` هستند. برای کارمند دوم سه روز حضور نمونه از تاریخ روز ساخته می‌شود. کد OTP در محیط توسعه `2244` است. Fixed OTP نباید در production استفاده شود. راهنمای اتصال پیامک: [SmsIrSetup.md](SmsIrSetup.md).

## اجرا

برای توسعه همراه با به‌روزرسانی زنده فرانت‌اند، از ریشهٔ پروژه اجرا کن:

```sh
npm run dev
```

`composer run dev` نیز همین راه‌انداز را اجرا می‌کند. آی‌پی شبکه در هر اجرا تشخیص داده می‌شود و آدرس برنامه روی پورت `8080` چاپ می‌شود. Laravel، Vite، صف و Scheduler هم‌زمان اجرا می‌شوند؛ با `Ctrl+C` متوقف می‌شوند. دستگاه‌های متصل به همان شبکه می‌توانند آدرس چاپ‌شده را باز کنند. این کار انتقال پورت مودم یا دسترسی عمومی اینترنت را تنظیم نمی‌کند.

آدرس برنامه و دامنه‌های session فقط برای فرایندهای همین اجرا تنظیم می‌شوند؛ فایل `.env` تغییر نمی‌کند. تنظیمات cacheشده Laravel پیش از اجرا پاک می‌شوند. برای انتخاب دستی آدرس یا پورت، مثلاً `DEV_HOST=192.168.100.22 DEV_PORT=8081 DEV_VITE_PORT=3002 npm run dev` اجرا کن. اگر پورت اشغال باشد اجرا متوقف می‌شود؛ ابتدا سرورهای توسعه قبلی را ببند. برای اجرای مستقل Vite از `npm run dev:vite` استفاده کن.

برای بازکردن برنامه، اجرای Vite یا `npm run dev` الزامی نیست. پس از هر تغییر فرانت‌اند یک‌بار `npm run build` اجرا کن؛ سپس با فایل‌های Build آماده، اجرای زیر کافی است:

```sh
php artisan serve
```

`SERVER_HOST=0.0.0.0` در `.env` محلی و `.env.example` تنظیم شده تا اجرای ساده `serve` از شبکه هم در دسترس باشد. پورت پیش‌فرض Laravel برابر 8000 است؛ پورت واقعی را از خروجی فرمان بخوان. پورت سفارشی با `php artisan serve --port=8093` و محدودکردن اجرا به خود سیستم با `--host=127.0.0.1` امکان‌پذیر است. سرور در حال اجرای قبلی برای اعمال تنظیم host باید یک‌بار دوباره راه‌اندازی شود. Queue و Scheduler در روش `serve` جداگانه اجرا می‌شوند؛ این فرمان فقط وب‌سرور است.

پردازش زمان‌بندی‌شده برای باطل‌کردن نوبت‌های گذشته هر دقیقه اجرا می‌شود. API هنگام خواندن نوبت‌ها نیز وضعیت را همگام می‌کند، اما در محیط عملیاتی Scheduler باید به‌صورت دائمی فعال باشد.

صفحه را از آدرس Laravel که فرمان اول چاپ می‌کند باز کن؛ پورت Vite صفحهٔ اصلی برنامه نیست.

برای تست روی موبایل، سرور را با `php artisan serve --host=0.0.0.0 --port=8000` اجرا و آدرس IP سیستم در شبکهٔ محلی (برای نمونه `http://192.168.100.15:8000`) را باز کن. مقدار `__SANCTUM_CURRENT_REQUEST_HOST__` در `SANCTUM_STATEFUL_DOMAINS` فقط برای محیط توسعه نگه داشته شده تا ورود session-based روی IP محلی و دامنه‌های موقت Tunnel نیز کار کند؛ در production باید دامنه‌های واقعی به‌صورت صریح جایگزین شوند.

دستورهای کامل Ubuntu، تنظیم Firewall، اتصال گوشی و Cloudflare Tunnel در [UbuntuMobileAccess.md](UbuntuMobileAccess.md) ثبت شده‌اند.

| `/panel/orders` | فهرست و جزئیات سفارش محصولات؛ فقط مدیر سالن |

| `/app/profile` | پروفایل شخصی؛ نیازمند ورود |

صفحات پنل به ورود و مجوز سالن نیاز دارند؛ کاتالوگ خدمات و محصولات عمومی است و سفارش، نوبت و پروفایل مشتری نیازمند ورود هستند. داده محصولات و سفارش‌ها در دیتابیس ذخیره می‌شود.

برای پرکردن برنامه کارکنان سالن آرا پیش از ارائه، پس از اجرای migration و Seeder پایه این دستور را اجرا کن:

```sh
php artisan db:seed --class=PresentationScheduleSeeder
```

این Seeder اختیاری است و در `DatabaseSeeder` اجرا نمی‌شود. برای هفته جاری و سه هفته بعد، روزهای خالی کارکنان را با چند بازه حضور پر می‌کند و سه کارمند نمایشی با خدمات مرتبط می‌افزاید. روزهای تعطیل سالن و برنامه‌های موجود حفظ می‌شوند؛ اجرای دوباره روز یا بازه تکراری ایجاد نمی‌کند.

پس از دریافت این نسخه `php artisan migrate` و `npm run build` اجرا شوند. رسیدهای پرداخت در `storage/app/private/product-order-receipts` نگهداری می‌شوند و نباید به Storage عمومی منتقل شوند. در جزئیات سفارش پنل، دکمه «ثبت تحویل / دریافت» برای هر قلم، تحویل و پرداخت را ثبت می‌کند. این ثبت دستی، اتصال به درگاه یا تأیید بانکی نیست.

## بررسی

```sh
npm run typecheck
npm run build
php artisan test
```

پس از Build می‌توان بدون Vite dev server و با سرور Laravel صفحات را دید. اگر `public/hot` به dev server خاموش اشاره دارد، ابتدا فرایند توسعه را به‌درستی متوقف کن و وضعیت آن فایل را بررسی کن.

بررسی مرورگر: مسیرها در عرض‌های 360، 768 و 1440، ورود مستقیم و Refresh، تاریخچهٔ مرورگر، وضعیت لینک فعال، Drawer راست، بستن با Escape و انتخاب لینک، کار با Tab، 404 و پایین صفحهٔ مشتری بررسی شوند.

## فونت و طراحی

نام «آرا» و سالن آرا نام نمایشی این پیش‌نمایش‌اند. فونت Vazirmatn به‌صورت محلی از پکیج `@fontsource/vazirmatn` بارگذاری می‌شود و درخواست خارجی فونت ندارد. مجوز SIL Open Font License 1.1 و نام پدیدآورندگان در `public/licenses/vazirmatn.txt` نگهداری شده‌اند. رنگ‌ها و اجزای MUI در `resources/js/theme/theme.ts` و چیدمان واکنش‌گرا در `resources/css/layout.css` قرار دارند.

## QR ورود مشتری

با حساب مدیر وارد پنل شوید و «QR ورود مشتری» (`/panel/access-qr`) را باز کنید. این قابلیت هم با `npm run dev` و هم با `php artisan serve` کار می‌کند و اجرای npm شرط ورود یا ساخت QR نیست. مشتری با اسکن کد صفحه `/app` را از آدرس شبکه و پورت وب‌سرور جاری باز می‌کند؛ گوشی و کامپیوتر باید به Wi-Fi مشترک متصل باشند و برنامه روشن بماند.

اگر پنل را از localhost باز کنید، Backend آی‌پی شبکه را از `DEV_HOST` معتبر یا مسیر شبکه سیستم و سپس hostname تشخیص می‌دهد و پورت را از همان درخواست جاری می‌گیرد. مقدار قدیمی APP_URL یا پورت Vite در QR استفاده نمی‌شود. برای درخواست با IP/دامنه قابل اشتراک، همان origin جاری حفظ می‌شود. پس از تغییر شبکه، صفحه را از آدرس جدید باز کنید یا دکمه «به‌روزرسانی آدرس و کد» را بزنید. کپی لینک روی HTTP شبکه، بازکردن برنامه و دانلود SVG نیز در صفحه موجودند.

## تنظیمات عمومی سالن

مسیر `/panel/settings` برای مدیر سالن و مدیر کل، نام، لوگو، معرفی و اطلاعات تماس/شبکه‌های اجتماعی را ذخیره می‌کند. Migration `2026_10_22_000001` باید اجرا شده باشد؛ برای تصاویر `public/storage` باید به public disk متصل باشد (`php artisan storage:link`). لوگو JPG/PNG/WebP تا ۲MB است و اطلاعات خالی اختیاری در اپ مشتری نمایش داده نمی‌شوند. تغییر لینک‌های اجتماعی روی کانال اعلان SMTP/Telegram یا موبایل ورود کاربران اثری ندارد.

## پیشنهاد مراقبتی و کد تخفیف

پس از اجرای migration جدید `2026_10_22_000002`، مدت اعتبار کد را در `/panel/settings` تعیین کنید. در ویرایش محصول، خدمات مرتبط، متن پیشنهاد و درصد اختیاری را فعال کنید. سپس انجام واقعی نوبت را ثبت کنید؛ برای نوبت باطل‌شده فقط مدیر دکمه «ثبت انجام واقعی خدمت» دارد. نوبت‌های Completed قدیمی خودکار پیشنهاد نمی‌سازند.

مشتری اعلان داخل برنامه و منوی «پیشنهادها» (`/app/recommendations`) را می‌بیند و می‌تواند محصول را با کد به سبد بفرستد. قبل از ثبت، Backend مبلغ را محاسبه و در ثبت موفق، کد شخصی یک‌بارمصرف را مصرف می‌کند. پرداخت همچنان با هماهنگی سالن است؛ اتصال درگاه اضافه نشده است.

## نصب برنامه مشتری روی گوشی

صفحه `/app/install` راهنمای نصب و وضعیت مرورگر را نمایش می‌دهد. ابتدا `npm run build` را اجرا کنید؛ Laravel فایل‌های خروجی و worker تولیدشده `public/sw.js` را سرو می‌کند و روشن‌بودن Vite شرط استفاده نیست. برای بررسی worker از Build استفاده کنید؛ حالت dev ثبت worker جدید انجام نمی‌دهد.

برای نصب روی گوشی، آدرس HTTPS معتبر لازم است. `http://localhost` برای تست روی همان کامپیوتر است؛ IP شبکه با HTTP امکان مرور دارد و نصب کامل PWA را فراهم نمی‌کند. برای HTTPS موقت، راهنمای Tunnel در `UbuntuMobileAccess.md` وجود دارد. QR آدرس origin جاری را می‌دهد؛ برای QR امن پنل را از آدرس HTTPS باز کنید. هیچ Tunnel یا لینک عمومی خودکار ساخته نشده است.

در Android از Chrome و گزینه Install app، در iOS از Safari و Share → Add to Home Screen استفاده کنید؛ در صورت ارائه گزینه Open as Web App آن را فعال کنید. امکان نصب خودکار در همه مرورگرها یکسان نیست و راهنمای دستی همیشه موجود است. نسخه نصب‌شده همچنان برای رزرو و اطلاعات به‌روز به میزبان روشن و اتصال نیاز دارد. قطع اتصال فقط صفحه راهنما نشان می‌دهد. پس از Build جدید، اعلان به‌روزرسانی در اپ منتظر اقدام مشتری می‌ماند تا فرم نیمه‌کاره خودکار Reload نشود.
